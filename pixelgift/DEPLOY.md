# Ручная публикация в `/pixelgift/`

Этот комплект подготовлен для адреса:

`https://cosmiclabindicators.com/pixelgift/`

Публикация в рамках подготовки v0.1 не выполнялась. Следующие действия предназначены для ручной загрузки владельцем хостинга.

## Что загружать

Используйте готовый архив `PixelGift_Website_v0.1.zip`. В нём находятся публичные HTML, CSS, JavaScript, локализации, логотип, favicon, оптимизированные изображения и документация. Исходные PNG Luma и локальные инструменты генерации в архив публикации не включены.

## Размещение

1. Откройте файловый менеджер хостинга, SFTP или FTP для `cosmiclabindicators.com`.
2. Найдите корневую папку действующего сайта. На разных хостингах она может называться `public_html`, `www`, `htdocs` или иначе.
3. Внутри корневой папки создайте новый каталог `pixelgift`.
4. Распакуйте **содержимое** архива в этот каталог. Правильный результат: `.../pixelgift/index.html`. Не должно получиться `.../pixelgift/PixelGift_Website_v0.1/index.html`.
5. Не заменяйте файлы в корне действующего сайта и не изменяйте существующие страницы.

Ожидаемая структура после загрузки:

```text
<web-root>/
└── pixelgift/
    ├── index.html
    ├── games.html
    ├── customize.html
    ├── how-it-works.html
    ├── faq.html
    └── assets/
        ├── brand/
        ├── css/
        ├── i18n/
        ├── images/
        └── js/
```

## Проверка относительных путей

Все рабочие ссылки и ресурсы в HTML используют относительные пути (`assets/...`, `games.html`, `customize.html`). Поэтому сайт может размещаться в `/pixelgift/` без изменения кода.

После загрузки проверьте напрямую:

- `https://cosmiclabindicators.com/pixelgift/`
- `https://cosmiclabindicators.com/pixelgift/games.html`
- `https://cosmiclabindicators.com/pixelgift/customize.html`
- `https://cosmiclabindicators.com/pixelgift/how-it-works.html`
- `https://cosmiclabindicators.com/pixelgift/faq.html`
- `https://cosmiclabindicators.com/pixelgift/assets/css/styles.css`
- `https://cosmiclabindicators.com/pixelgift/assets/images/hero-world-1600.webp`

Если главная страница открывается, а стили или изображения возвращают 404, проверьте, что папка `assets` находится рядом с `index.html`, регистр букв сохранён и архив не создал лишний вложенный каталог.

## MIME-типы и кэш

Современный хостинг обычно уже отдаёт WebP и AVIF с правильными MIME-типами. При проблемах администратор сервера должен настроить `image/webp` для `.webp` и `image/avif` для `.avif`. Файлы HTML желательно кэшировать коротко, а версионируемые изображения, CSS и JS — дольше. Эти настройки относятся к серверу и намеренно не навязываются комплектом сайта.

## Финальная ручная проверка

1. Откройте каждую страницу и все пункты меню.
2. Переключите RU, DE и EN на двух разных страницах; выбор должен сохраниться.
3. На странице конструктора пройдите шесть шагов.
4. Загрузите JPG/PNG/WebP меньше 8 MB, проверьте предпросмотр, затем удалите изображение.
5. Убедитесь, что Pixel Commando и Pixel Action помечены «Скоро» и их кнопки недоступны.
6. Нажмите «Отправить заявку»: должно появиться сообщение о том, что приём заказов не открыт, без сетевой отправки.
7. Проверьте сайт на смартфоне и компьютере, включая клавиатурную навигацию.
8. Проверьте консоль браузера: ошибок JavaScript быть не должно.

## Подключение backend в будущем

Точка будущей интеграции — обработчик `submit` в `assets/js/customizer.js`. До добавления backend необходимо отдельно определить защищённый API заказов, серверную загрузку файлов, согласие на обработку данных, проверку MIME/размера на сервере, антиспам, аутентификацию, платёжного провайдера и правила выдачи DEMO/FULL APK. Секреты и API-ключи должны храниться только на сервере.
